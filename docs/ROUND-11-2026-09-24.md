# Round 11 — Reality Sky Studio: Every Reality Owns Its Sky (2026-09-24)

> "Why only a specific code do I have to write? Imagine I like a picture and
> want it as the background, as the universe surface… upload or save a photo
> under that reality folder and the project makes that photo the background."

**Yes — and it ships today.** Every reality can now hold its own uploaded photo
sky, stored inside *that reality's own folder*, and the 3D engine paints it as
the universe backdrop. Reality A's picture never leaks into Reality B.

## The Isolation Contract

```
src/realities/<folder>/
├── index.ts      ← the reality's code (existing)
├── surface.ts    ← the reality's color script (existing)
├── data.json     ← the reality's worlds & diary (existing)
├── sky.json      ← NEW — the sky registry (active photo, roster, mood)
└── assets/       ← NEW — this reality's uploaded sky photos
    └── sky-xxxx.jpg
```

Sky is now a first-class reality file, exactly like code and data. The daemon
protects it, rename/restore carry it, purge destroys it — for free, because it
lives inside the folder.

## Server — `server/skyStore.ts` (new) + 6 routes

- `GET  /api/realities/sky/status?folder=` → full registry
- `POST /api/realities/sky/upload` → base64 image into `assets/`, auto-activates
  the first upload; validates mime (png/jpeg/webp/gif/avif), 6 MB cap, 8-photo cap
- `POST /api/realities/sky/activate` → switch or deactivate (`photoId: null`)
- `POST /api/realities/sky/delete` → file + registry entry, active cleared
- `POST /api/realities/sky/settings` → mood sliders, clamped 0..1
- `GET  /api/realities/sky/asset/:folder/assets/:file` → serves the bytes with
  strict name whitelisting, `isInside` containment, ETag (`304` on unchanged)
- A catch-all guard on the asset prefix rejects malformed requests instead of
  letting them fall through to the SPA.

Every path passes `sanitizeFolderName` + `isInside`, the same hardening as all
reality-folder APIs.

## Client — `src/sky/skyRegistry.ts` (new)

Per-reality manifest cache, folder resolution (recorded map → build-time map →
derived name), upload through a **2:1 equirectangular canvas** (cover-crop, so
sphere mapping never pole-stretches a photo), activate/delete/settings calls,
and an `onSkyChanged` event bus that the engine and the editor panel both
listen to. Reality switches warm the cache in the background so warp-in is instant.

## Engine — `src/engine/surface/photoDome.ts` (new) + surface wiring

The **photo dome**: an inverted sphere at r=300,000 sitting between the
procedural shader cosmos (below) and the far star shell (above). Your photo
becomes the sky while the real 3D stars keep twinkling over it and the
reality's own light breathes through from beneath.

- **Layer stack:** procedural cosmos → photo dome (renderOrder −99) → stars
- **Mood sliders:** Presence (photo↔cosmos blend), Depth (dim), Nebula (blur),
  Vignette, Drift (slow parallax breathing) — all live via uniforms
- **Crossfade:** switching realities fades the old sky out over ~1.2s; the fade
  holds while the new texture loads so the raw cosmos never flashes
- **Kamui-aware:** the tear swallows the photo dome with the rest of the sky
- `applyActiveSky()` on the engine runs on every `setReality` (fire-and-forget);
  desktop additionally fetches the registry itself so skies work without the
  web server. `setRendering(false)` (vault mode, hidden tabs) also hides the dome.

## UI — Sky Studio tab in the Reality Editor

Double-click any reality ring (or open the Core Console) → new **Sky** tab:

- Drag-and-drop zone or file picker (png/jpg/webp/gif/avif, 6 MB)
- Photo gallery with active badge, hover activate/remove actions
- "Return to the pure procedural cosmos" deactivation
- Five live mood sliders with per-slider hints

  bin/restore round-trip or a hand-deleted folder.

- Verified live: upload into a *missing* folder → folder recreated, registry
  healthy, photo active. Typecheck + build green.
