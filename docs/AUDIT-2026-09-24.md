# Deep Debugging Audit — Full-Project Sweep (2026-09-24)

Exhaustive pre-upgrade audit requested before any further features. Scope:
persistence pipelines, disk-sync machinery, engine lifecycle, disposal paths,
sky pipeline, server routes, state integrity.

## Findings & Fixes (6 shipped, all verified)

### 1. The disk-sync heartbeat could die forever — CRITICAL
`realitySync.tick()` had no error boundary: one thrown exception (any glitch in
`flushDiskQueue` or the poll) cancelled the schedule chain, `void tick()`
swallowed the rejection, and the 3s reality⇄disk mirror went **silently dead
for the rest of the session** — the reload-storm protection, self-heal, and
retry queue all ride this heartbeat.
**Fix:** `tick()` now wraps `tickBody()` in try/catch, publishes the failure to
`diskSync.lastError`, and always reschedules (degraded backoff).
**Verified live:** heartbeat cycling (lastSync age ~4s at probe), connected,
zero console errors.

### 2. `data.json` world-database writes were fire-and-forget — HIGH
`exportRealityData` used raw `realityApi` (no success check, no retry). A
server blip silently dropped the reality's world mirror until some unrelated
future switch. Bin operations already had the reliable path; data writes didn't.
**Fix:** routed through `syncedRealityApi` (awaited, success-checked, retry
queue) + a user-visible warn toast on failure. Verified the endpoint 200s.

### 3. A transient fetch could wipe a healthy sky cache — MEDIUM
`fetchSky` adopted an **empty manifest** on any failure — one hiccup while
switching realities and a real photo sky silently vanished until re-fetch.
**Fix:** on failure, keep the cached manifest; only adopt a genuine empty sky
when nothing better is known.

### 4. Sky-apply race: last-finished beat last-chosen — MEDIUM
Two rapid reality switches could interleave async texture loads; the slower
older load would win the dome (`hasMap`), showing reality A's sky inside
reality B.
**Fix:** monotonic `applySeq` in the PhotoDome — a superseded load abandons
silently. Self-contained; no engine changes needed.

### 5. Corrupt stored state silently reseeded over the evidence — HIGH
`loadState`'s catch block fell through to a fresh seed, overwriting the broken
payload on the next persist. A single bad byte could cost a whole universe.
**Fix:** preserve the raw broken string at `my-universe:v4:recovery`, log the
error, toast (deferred past React mount) — then seed fresh. Recovery is now
always possible by hand.

### 6. Persistence catch conflated quota with serialization failure — MEDIUM
`persistState`'s catch assumed quota; a `JSON.stringify` failure (circular
ref, huge payload) got the same "storage is full" message and no protection.
**Fix:** classify the error (quota vs serialization), message accordingly, and
snapshot the last-good store to `:recovery` before anything can overwrite it.

## Verified-Intact Systems (inspected, no action needed)

- **Engine `dispose()`** — animation loop stopped, every canvas/window
  listener removed, scene deep-disposed, composer/renderer disposed,
  QUALITY_CHANGE listener removed. No leak on hot reload.
- **CameraRig dispose** — all 5 listeners removed.
- **Kepler accelerator** — `inflight` guard prevents overlap; TS backend
  short-circuits; results one tick behind is by design (seamless).
- **Reality daemon** — create-folder dedup, `markRecentlyWritten` grace,
  bin move/restore/purge, rename; path sanitization + `isInside` on every API.
- **State boot** — v4 container migration, ownership repair, reachability
  healing, genesis-shadow repair all robust; desktop hydrate is
  content-equality-guarded (no reload loops).
- **Sky routes** — traversal guard, ETag 304s, whitelist-only asset names,
  SPA-fallthrough rejection (verified in the Round-11 probes).
- **Memoization** — signature covers orbit shape + radius + kind; live fields
  re-solve per call; negative-speed retrograde orbits verified Round 10.

## Deferred Recommendations (for a future hardening wave)

1. **localStorage quota ceiling** — today's payloads will eventually hit the
   ~5 MB wall; the desktop tier already bypasses it, but web-only users need
   the payload store (OPFS) to hold more than diary attachments.
2. **Server input caps** — `express.json({ limit: '10mb' })` is global; the
   non-sky routes could drop to ~256kb with the sky upload on its own limiter.
3. **Engine hot-reload double-boot guard** — Vite HMR can mount two engines
   in dev (the cancel flag covers most paths; a `window.__ENGINE__` presence
   check would make it bulletproof).
4. **`data.json` size cap** — a reality with thousands of entries can grow
   its mirror unbounded; chunking or entry-count-based externalization later.
