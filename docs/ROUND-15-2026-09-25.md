# Round 15 — The File Manager Becomes a Pro Explorer (2026-09-25)

> "Go to the internet — GitHub, GitLab — find a great advanced futuristic
> open-source File Manager and add its power to our vault."

Research first, then a native port — **zero new dependencies**, zero changes to
the EFS persistence shape. The patterns came from three battle-tested projects:

| Source project | Patterns ported |
|---|---|
| **Spacedrive** (Rust VDFS, 40k★) | tags as first-class locations, recents smart collection |
| **Files** (files-community, Windows) | tab strip, details/list view |
| **Double Commander** | dual-pane, full keyboard navigation |

BUILD: **R39**. Typecheck clean, production build green, module probes pass.

## What shipped (all in `src/ui/FileManager.tsx`)

1. **Tabs with per-tab history (Files/Sigma)** — each tab owns `{ cwd,
   history[], hIndex }`. The tab strip sits above the listing: click to
   switch, hover-✕ to close, `+` to open a new tab inheriting the current
   directory. `Ctrl+T` / `Ctrl+W` / `Alt+←/→` (back/forward through history).

2. **Dual-pane split view (Double Commander)** — toolbar toggle. Pane B runs
   its own directory, breadcrumb, and selection (`selB`); click focuses a pane
   (focused pane drives keyboard + inspector). **Cross-pane drag lands as a
   zero-byte CoW fork** — the pane-B drop handler routes `text/efs` payloads
   through the existing `efsMoveNodes`/`efsCopyNodes` pipeline, so dragging
   from A to B forks shared extents without allocating a byte.

3. **Tag browser (Spacedrive)** — a new "collections" section in the locations
   rail: every tag in the vault, sorted by usage, with counts. Clicking one
   opens a virtual collection listing every node carrying that tag (dirs +
   files), navigable and draggable — tags now work like Spacedrive's
   tag-locations: structure *beyond* the folder tree.

4. **Recents smart collection** — the 40 most recently sealed files
   vault-wide, one rail-click away, with open/lock on double-click.

5. **Details/list view (Files)** — toolbar toggle (grid ⇄ list). List rows
   carry real columns: name · kind · size · modified; still marquee-
   selectable and draggable. The grid view remains the default.

6. **Keyboard navigation (Double Commander)** — arrow keys walk the visible
   objects (grid-aware: 4 cards per row; list-aware: one row per step),
   Enter opens the selected directory/file (locked files route to the
   key-ring), all previous shortcuts (F2, Del, Ctrl+A/C/X/V, Backspace,
   Esc) unchanged.

## Verification

- `npm run typecheck` clean; `npm run build` green (server.cjs 40.1kb).
- Module probes on the live dev server: `FileManager` and `VaultUI` export
  cleanly, BUILD R39 live in the app, EFS store healthy (nodes enumerated,
  tag collection logic exercised against the real store — empty-tag edge
  handled: the tags section simply renders nothing until a tag exists).
- Deep-UI probe honestly blocked by design: the vault's identity gate asks
  for the owner's master key, which verification must never bypass. The
  feature layer is fully typed and module-verified; visual confirmation is
  one click away for the owner (vault → File Manager).

## Design law kept

No new dependencies, no persistence migration, no engine changes — the whole
upgrade is the explorer layer, exactly like the research targets: powerful
surface, untouched core.
